
# 引言

  

做一定复杂度的需求时，通常需要写逻辑设计文档，既方便他人了解需求实现细节，又帮助自己梳理逻辑。

  

但你是否在一段时间过后想回顾需求时，翻看逻辑设计文档，却总是回想不起其中的某些细节，比如核心代码内容？踩过的某个坑是如何解决的？做这个需求的时间花销？...

  

或许是因为逻辑设计文档的结构不完善，导致许多当时认为不重要的细节都没有被记录，久而久之就忘了。

  

本文介绍前端逻辑设计文档的一篇模板，其中尽量记录一些容易被遗忘的小细节，帮助你更好地理解需求、做好需求、回顾需求。

## 一、需求速览

  

> 需求名称：
> 需求进度：

这部分罗列需求名称、需求进度。

其中需求进度很重要，这里记录从需求开始到结束的所有时间节点。你可以清晰地看到需求的时间线，帮助整体回顾需求。另外知道你花了多少时间去做了哪些事，能复盘时间利用率。示例如下：


| 时间段      | 进展 |
| ----------- | ----------- |

| 2025.9.20 ~ 2025.9.24   | 前端开发，提 PR        |


## 二、需求分析


### 1. 业务价值

用1-2句话说明业务价值，不是功能描述。这一点促使你去思考需求的业务价值，尽量做有意义、有价值的事情，而不仅仅着眼于技术实现。

业务价值应该聚焦于带来的好处、解决的深层问题、以及创造的积极影响。它通常与以下几个方面挂钩：
1. 提升效率： 节省了谁的时间？简化了哪个流程？
2. 加强安全： 降低了什么风险？保护了什么资产？
3. 降低成本： 减少了哪些不必要的开支？（如打印浪费、泄密损失）
4. 促进协作： 如何让内外部协作更顺畅？
5. 满足合规： 是否帮助客户满足了审计、归档等法规要求？

### 2. 现状分析
>1. 背景
>2. 现状
>3. 实现目标

说明需求相关的背景、现状。并详细列举需要实现的具体目标、功能点，后续逻辑设计依据这些具体目标展开。


### 3. 相关需求及文档
罗列 PRD、设计稿、后端逻辑设计、MR/PR、测试文档等，并记录对应的合作人员。

资料备份区，方便回顾。

## 三、实现分析（主要技术决策）

这是最有价值的部分，记录你关于主要技术决策的思考过程。一定要事无巨细的记录下来，包括你觉得很简单的点，防止知识诅咒（一旦了解了某种知识，就很难站在没掌握这个知识的角度，去思考和理解他人）

分决策点叙述，每个点详细记录自己的思考过程、考虑过的方案、最终选择、理由等。


## 四、逻辑分析
技术实现摘要 (执行部分)

### 1. API 变更
记录相关的 API 变更。

### 2. UI/交互要点

列举UI/交互要点，针对每个要点，是如何实现的。记录这一点也能方便测试。


### 3. 核心代码片段

记录核心改动文件、核心代码片段（只记录最关键的、能体现核心逻辑的代码）

如：
```
src/
├── views/document/preview.vue          # 主要业务逻辑
├── components/document/PrintButton.vue # 打印按钮组件 (如有)
└── assets/styles/print.css            # 打印样式
```

``` javascript
// preview.vue 中的权限检查
async checkPrintPermission() {
  try {
    const perm = await getDocumentPermission(this.docId);
    this.canPrint = perm.canPrint;
  } catch (error) {
    console.error('检查打印权限失败', error);
    this.canPrint = false; // 失败时默认无权限
  }
}
/* print.css 中的关键样式 */
@media print {
  .header, .footer, .toolbar {
    display: none !important;
  }
  .document-content {
    width: 100% !important;
    margin: 0 !important;
  }
}
```

## 六、总结与反思

### 1. 遇到的坑与解决方案

这一步也很重要，通常在测试阶段会发现一些坑，记录在这里方便回顾。
如：
1. 问题：Chrome和Firefox对打印边距处理不同
解决：在打印样式中统一设置 margin: 0.5in
2. 问题：动态加载的内容在打印时可能缺失
解决：在调用window.print()前确保所有内容已渲染完成

### 2. 可改进点
记录一些思考、关键洞察。
如：
  - 浏览器的打印样式支持度差异是主要风险点
  - 权限字段需要与后端明确数据类型（布尔值 vs 字符串）

如果重做我会改进什么？
如:
  - 考虑做一个打印预览组件，让用户在实际打印前看到效果
  - 将打印样式做成可配置的，适应不同类型的文档

### 3. 一句话总结

用一句话概括这个需求的精髓，方便快速浏览。

例：“一个依赖新权限字段的、调用浏览器原生打印的轻量级功能，重点在于处理好打印样式。”
